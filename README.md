## 项目介绍

开发 USDT 支付系统时，订单号、金额精度、支付状态和商户对账是基础环节。本项目用少量代码展示这些环节，方便阅读、运行和作为需求讨论的起点。

项目采用 Python 标准库，无需安装第三方依赖。所有金额以整数记录，展示时格式化为六位小数；这只是本演示的精度约定，真实集成时应读取目标代币的精度。

## 已有示例功能

- 创建带唯一商户订单号的模拟支付订单。
- 校验金额，避免使用浮点数直接计算。
- 将订单标记为“模拟已支付”，重复操作不会重复计入汇总。
- 查看本地订单列表及按状态汇总的金额。
- 使用 SQLite 保存模拟数据，重启后仍可查询。

## 快速运行

环境：Python 3.10 或更高版本。

```bash
git clone https://github.com/haohao866/-usdt-otc-.git
cd -- -usdt-otc-
python payment_demo.py create DEMO-001 10.50
python payment_demo.py list
```

复制创建命令返回的 `order_id`，替换下面的 `ORDER_ID`：

```bash
python payment_demo.py simulate-pay ORDER_ID
python payment_demo.py summary
```

数据默认写入项目目录的 `demo.sqlite3`。这是本地演示数据，不代表链上余额或真实成交。

运行测试：

```bash
python -m unittest discover -s tests -v
```

## 常见问题

### 可以直接接收 USDT 吗？

不可以。当前示例只演示本地订单逻辑，尚未接入钱包、区块链节点、代币合约、交易监听或真实支付回调。

### USDT支付系统和U卡是同一类系统吗？

不是。支付订单系统与卡产品涉及不同的功能和服务方，本项目不提供发卡、卡片充值或卡组织接入功能。

### 仓库名称里有 OTC，是否包含交易系统？

当前仓库仅包含支付订单模拟代码，不包含 OTC 撮合、法币兑换或微信兑换 USDT 功能。
